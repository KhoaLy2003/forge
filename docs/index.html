Two scaffolding CLIs that generate a ready-to-build project.

Forge generates a full Java 21 + Spring Boot 4 + PostgreSQL service. Forge Web generates a full React + TypeScript + Vite + Shadcn/ui dashboard. Both walk you through a wizard, preview the file tree, and validate the result by actually compiling or building it, so starting new work is faster than copying an old project by hand.

One pipeline, two targets

Both CLIs share the same wizard, preview, render, and validate pipeline shape, applied to a different stack.

Forge

backend/ · Java + Spring Boot 4 + PostgreSQL

  • Java 21, Spring Boot 4, Maven, PostgreSQL 16
  • Feature-based packages, a shared common/ layer, and one end-to-end example/ slice to copy
  • Liquibase migrations, docker-compose for local Postgres
  • Actuator, springdoc-openapi, and a Testcontainers-backed test suite
forge new

Forge Web

frontend/ · React + TypeScript + Vite + Shadcn/ui

  • React 18, TypeScript, Vite, React Router, Tailwind v4
  • A curated Shadcn component set, themed entirely from design tokens
  • A sample CRUD dashboard wired to a mock or real API client
  • Static 404, error, loading, and empty-state pages included
forge-web new

Install

Both packages install editable into a single virtual environment. 

# from the repo root
py -m venv .venv
.venv\Scripts\pip install -e "./backend[dev]"
.venv\Scripts\pip install -e "./frontend[dev]"

# then run either CLI
.venv\Scripts\forge new
.venv\Scripts\forge-web new

How it works

Every generated project passes through the same four stages before it reaches disk.

Wizard
Prompts for anything missing from the CLI flags, validating as it goes.
Preview
Renders the resolved file tree and asks for confirmation before writing anything.
Render
Writes the templated project, refusing to overwrite an existing target directory.
Validate
Checks the generated structure and actually compiles or builds the result.
