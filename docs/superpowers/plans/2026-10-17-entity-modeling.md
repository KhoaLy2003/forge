# Backend Entity Modeling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Repo conventions that override the skill defaults:** do NOT run `git commit`/`git push` at any step. Steps describe *what* to write and *which signatures*; write real code fresh and verify with a real compiler/test run. **Order:** implement after the observability and notification plans (Liquibase numbering: notifications take `002`, entity changelogs start at `003`).

**Goal:** `forge new` can generate real domain entities (fields + relational relationships) with full CRUD slices and Liquibase schema, from `forge.yaml` or the wizard.

**Architecture:** Pydantic entity model → rule validation and dependency ordering → type table → a fan-out renderer that renders a `templates/_entity/` slice once per entity on top of `_shared`; Liquibase files generated per entity in topological order, join tables, then FK/index changesets, with the master changelog built by a Jinja loop.

**Tech Stack:** Python 3.11 (Typer, Jinja2, pydantic, PyYAML, pytest), generated Java 21 / Spring Boot 4 / MapStruct / Liquibase SQL.

**Spec:** `docs/superpowers/specs/2026-10-17-entity-modeling-design.md`. The `Example` slice under `backend/templates/_shared/src/main/java/{{ package_path }}/example/` and `.../src/test/.../example/` is the structural reference for the entity templates.

## Global Constraints

- Entities require `base-layered`; `template: minimal` + entities is a validation error.
- Entity names PascalCase, singular, unique, not in `JAVA_RESERVED_WORDS`; field/relation names camelCase, unique per entity, not reserved, not in `{id, version, createdAt, updatedAt, deletedAt}`.
- Table name default = snake_case plural; reserved SQL words rejected with a message suggesting `table:`.
- Types and mappings exactly as the spec table: `string, int, long, decimal(precision+scale required), boolean, date, instant, uuid, enum(values required)`; modifiers `required, unique, default`.
- Relations: `many-to-one` (owning, `LAZY`), `one-to-many` (inverse; unidirectional unless `inverse:`/`mappedBy`), `many-to-many` (join table, composite PK, owning side declared once), `one-to-one` (= many-to-one + unique FK). All `LAZY`; FK indexes; `ON DELETE RESTRICT`; cascade/`orphanRemoval` only on one-to-many composition. DTOs expose ids, never nested entities.
- IDs are `UUID` from `BaseEntity` (audit columns, `version`, `deletedAt`); entities extend it.
- Liquibase: `.sql` formatted changelogs, numbered from `003` in topological order (`001` example, `002` notifications are fixed); then join tables; then FK/index changesets; every changeset has `rollback`; master changelog generated by a Jinja `for` loop.
- With entities declared, the `Example` slice and `001-create-example-table.sql` are excluded; with no entities behavior is byte-identical to today.
- `forge.yaml` may carry `project_name`, `group_id`, `artifact_id`, `template`, `entities`; CLI flags override file values. Entities are never CLI flags.
- Repository (Testcontainers) tests are generated per entity but run only in CI; locally generated Java is compiled with `test-compile`.
- `_shared` rendering path is untouched; `jinja2.StrictUndefined` stays on; `{{ }}` literals in templates use `{% raw %}`.
- New modules (one purpose each) under `backend/core/`: `entity_spec.py`, `entity_rules.py`, `type_map.py`; fan-out in `renderer.py`.
- `_testing/` at repo root is a git-ignored scratch area; nothing written outside the repo root.

## Review Focus

- Entity named `Order` or `User` → rejected before anything is written, message suggests `table: customer_orders` (Task 3).
- Two entities that require each other (required many-to-one both ways) → cycle error naming both; optional cycle is accepted and generates valid FK ordering (Task 4).
- `mappedBy` pointing at a non-existent or non-owning relation, or a many-to-many declared on both sides → clear error (Task 4).
- `forge.yaml` with a typo'd type (`strng`) or unknown key → error names the entity, field and valid values (Task 1).
- CLI flag disagrees with `forge.yaml` (e.g. `--name`) → flag wins; missing required values still reach the wizard (Task 6).
- No entities declared → output tree identical to today and `Example` slice present (Task 7).
- Generated project with all four relation kinds, every type and an enum compiles (`test-compile`) and its Liquibase master lists every changelog in dependency order (Tasks 9–11).
