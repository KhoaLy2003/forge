A Spring Boot 4 + PostgreSQL REST service, generated by [Forge](https://github.com/).

## Tech Stack

- Java 21
- Spring Boot 4
- PostgreSQL 16
- Liquibase (schema migrations)
- Lombok
- MapStruct
- springdoc-openapi (Swagger UI)
- Spring Boot Actuator

## Prerequisites

- JDK 21+
- Maven
- Docker — for the local Postgres container and for the Testcontainers-backed
  tests in `mvn test`

## Project Structure

```
src/main/java/{{ base_package.replace('.', '/') }}/
├── common/     cross-cutting infrastructure
│   ├── config/     filters, JPA auditing, OpenAPI setup
│   ├── dto/        ApiResponse envelope, pagination wrappers
│   ├── entity/     BaseEntity (id, timestamps, soft delete, version)
│   ├── exception/  GlobalExceptionHandler and domain exceptions
│   └── util/       shared helpers (e.g. pagination)
└── example/    a demonstrated domain slice
    ├── controller/
    ├── dto/
    ├── entity/
    ├── mapper/
    ├── repository/
    └── service/
```

`common/` holds infrastructure shared by every feature and should rarely need
changes. `example/` is a reference CRUD slice — when adding a new domain,
create a sibling package and mirror its six subpackages
(`controller`, `dto`, `entity`, `mapper`, `repository`, `service`).

## Getting Started

```
docker compose up -d
mvn spring-boot:run
```

The app runs with the `dev` Spring profile by default (set in
`application.yml`), which points at the local Postgres container started
above.

## API Documentation

- Swagger UI: http://localhost:8080/swagger-ui.html
- Raw OpenAPI spec: http://localhost:8080/v3/api-docs

Example request against the `example` resource:

```
curl -X POST http://localhost:8080/api/v1/examples \
  -H "Content-Type: application/json" \
  -d '{"name": "sample"}'
```

Every response is wrapped in a common envelope:

```json
{
  "success": true,
  "message": "Example created successfully",
  "data": { "id": "...", "name": "sample", "status": "ACTIVE" }
}
```

## Configuration & Profiles

- `application.yml` — profile-independent defaults (server port, Actuator
  exposure, Liquibase changelog location, logging pattern)
- `application-dev.yml` — local Postgres connection, SQL logging on, Swagger
  UI enabled
- `application-prod.yml` — reads `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` from
  the environment, SQL logging and Swagger UI disabled

Run the prod profile with:

```
SPRING_PROFILES_ACTIVE=prod DB_URL=... DB_USERNAME=... DB_PASSWORD=... mvn spring-boot:run
```

## Database Migrations

Schema changes are managed with Liquibase using the Formatted SQL changelog
style. Migrations live under
`src/main/resources/db/changelog/`, registered in
`db.changelog-master.xml`.

To add a migration: create a new `NNN-description.sql` file with a
`--liquibase formatted sql` header and a `--changeset author:id` block (see
`001-create-example-table.sql` for an example), then register it in the
master changelog.

## Testing

```
mvn test
```

Runs unit tests, `@WebMvcTest` controller tests, and Testcontainers-backed
repository tests — this **requires Docker running locally**.

```
mvn test-compile
```

Compiles all main and test sources without running anything, so it does not
need Docker.

## Code Style

Formatting is enforced with [Spotless](https://github.com/diffplug/spotless)
using Google Java Format:

```
mvn spotless:check   # verify formatting (bound to `mvn verify`)
mvn spotless:apply   # auto-fix formatting
```

The generated code is pre-formatted for common group ids (e.g.
`com.example`). Because Google Java Format's import ordering and line-wrap
decisions depend on the literal length of your package name, an unusual
`--group-id` can occasionally leave `spotless:check` failing right after
generation — if so, just run `mvn spotless:apply` once to fix it for good.

## Observability

- Health check: http://localhost:8080/actuator/health
- Build/app info: http://localhost:8080/actuator/info
- Every request gets an `X-Correlation-ID` header (generated if not supplied
  by the caller, echoed back on the response) that is attached to the
  logging MDC, so it appears in every log line emitted while handling that
  request.

## Database Credentials

The default Postgres credentials (`forge`/`forge`) are hardcoded in
`docker-compose.yml` and `src/main/resources/application-dev.yml` for local
development convenience only. Replace them with the `DB_URL` /
`DB_USERNAME` / `DB_PASSWORD` environment variables (see the prod profile
above) before running this project anywhere beyond a local dev machine.
