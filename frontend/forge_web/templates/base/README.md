# {{ app_display_name }}

A Vite + React + TypeScript + Shadcn/ui dashboard, generated by Forge Web.

## Tech Stack

- React 18 + TypeScript
- Vite (SPA) + React Router
- Tailwind v4 + Shadcn/ui
- TanStack Query (data fetching/caching)
- react-hook-form + zod (forms/validation)

## Prerequisites

- Node.js 18+
- npm

## Getting Started

```bash
npm install
npm run dev
```

Opens the dev server (default http://localhost:5173). The app runs against
**mock data** out of the box — no backend required to explore it.

## Mock vs. Real API

Every data operation goes through `src/lib/api-client/`'s `ApiClient`
interface (`listItems`, `getItem`, `createItem`, `updateItem`,
`deleteItem`), never a direct `fetch` call from a component. Which
implementation actually runs is controlled entirely by one environment
variable:

```
VITE_API_MODE=false   # in-memory fixture data, ~300ms simulated latency (default)
VITE_API_MODE=true    # fetch() against VITE_API_BASE_URL
```

Switching from prototyping against mock data to a real backend is a `.env`
edit, not a code change — set `VITE_API_MODE=true` and point
`VITE_API_BASE_URL` at your API, and every screen that already uses the
`useItems`/`useCreateItem`/etc. hooks starts hitting it.

## Environment Variables

A `.env` file (generated for you, pre-filled from what you gave `forge-web
new`) and a documented `.env.example` both ship in this project:

| Variable | Purpose |
|---|---|
| `VITE_APP_NAME` | Shown in the page `<title>` and anywhere the app name renders |
| `VITE_API_MODE` | `true` or `false` — `true` selects the real API client, `false` (default) selects mock |
| `VITE_API_BASE_URL` | Base URL the real client sends requests to |

Vite only loads `.env`, not `.env.example` — if you ever delete or rename
`.env`, copy it back from `.env.example` and fill in real values.

## Theming

Every color, font size/weight, spacing step, corner radius, and shadow used
anywhere in this project is a CSS custom property defined once in
`src/styles/theme.css` (e.g. `--color-primary`, `--radius-sm`,
`--spacing-lg`). Components consume these through Tailwind utility classes
(`bg-primary`, `rounded-sm`, `p-lg`) generated from that file — none of them
hardcode a color or pixel value directly. **To restyle the app, edit
`theme.css` — the change applies everywhere at once**, with no per-component
edits needed. Visit `/components` after `npm run dev` to see every primitive
at a glance while you tune values.

## Continuous Integration

This project ships with a GitHub Actions workflow at
`.github/workflows/ci.yml` that builds the app, and runs CodeQL, a Trivy
filesystem scan, a dependency review (on pull requests), and zizmor
(workflow linting) on every push/PR to `main`. The `dependency-review` job
requires a one-time manual step on GitHub: enable Dependabot/vulnerability
alerts on your repo (Settings → Code security → enable "Dependency graph"
and "Dependabot alerts") — without that, the job will fail even though
nothing is wrong with your code.

## Adding a New Page

1. Create the page component under `src/pages/<feature>/`.
2. Add a `<Route>` for it in `src/App.tsx`.
3. If it needs a nav entry, add a `NavLink` in
   `src/components/common/nav-sidebar.tsx`.
4. If it needs data, add hooks to `src/lib/hooks/` following the
   `use-items.ts` pattern (wrap `apiClient` calls in `useQuery`/`useMutation`).
